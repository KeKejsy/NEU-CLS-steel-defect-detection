## 二、分类网络（成员 B，2 个）

两个都直接使用 **`paddle.vision.models` 里的官方实现 + ImageNet 预训练权重**（不从零设计结构），
输入 **200×200 不缩放**（数据集原图尺寸），ImageNet 均值方差归一化，标签平滑 0.1，
Momentum SGD + 线性 warmup + 余弦退火。

| 项 | ResNet50 | MobileNetV3-small |
|---|---|---|
| 主干结构 | `conv1` 7×7/s2 + maxpool → 4 个 Bottleneck 阶段（3/4/6/3 块）→ 全局池化 | 深度可分离卷积 + SE 通道注意力 + h-swish，倒残差块 |
| 分类头 | FC(2048 → 6) | FC(1024 → 6) |
| 参数量 | 2357.34 万 | 153.61 万（相差 15.3 倍） |
| 训练配置 | batch 16 / 20 轮 | batch 32 / 30 轮 |
| 收敛速度 | 第 2 轮验证集到 100% | 第 20 轮才追平 |
| 单张推理 | 86.0 ms（11.63 FPS） | 10.5 ms（95.19 FPS，快 8.2 倍） |
| 模型体积 | 90.1 MB | 6.0 MB（1/14.9） |

> 唯一一处非默认设计：**保留三通道**。数据内容虽是灰度，但文件按 RGB 存储，
> 保留三通道才能直接复用 ImageNet 预训练权重，不必改网络第一层。

## 三、单阶段检测器（成员 C，2 个，均为原生 Paddle 手写）

### 3.1 YOLOv3 —— anchor-based、三尺度

```
输入 416×416×3
└─ Darknet53 主干（5 次下采样，逐层写死不循环推导）
   conv0  3×3/s2  → 32     /2
   conv1  3×3/s2  → 64     /4
   conv2  3×3/s2  → 256    /8   ──▶ f3 (52×52×256)
   stage2 1×1↓64 → Bottleneck×2 → 1×1↑256
   conv3  3×3/s2  → 512    /16  ──▶ f4 (26×26×512)
   stage3 1×1↓256 → Bottleneck×8 → 1×1↑512
   conv4  3×3/s2  → 1024   /32  ──▶ f5 (13×13×1024)
   stage4 1×1↓512 → Bottleneck×8 → 1×1↑1024
   conv5  3×3/s2  → 1024   /64   （不返回，仅为 stage5 提供更深语义）
   stage5 1×1↓512 → Bottleneck×4 → 1×1↑1024
└─ FPN：三路 1×1 卷积把 256/512/1024 统一压到 256
        → 自顶向下上采样逐元素相加 → 每层接 5 个 3×3 卷积平滑
└─ 检测头：每个尺度 3 个 anchor × (5 + 6) = 33 通道
           输出 (B, 3, H, W, 11) —— 每格 anchor 一条 (tx,ty,tw,th,obj,cls×6)
```

**坐标**：全程归一化 cxcywh（`im_size` 只用于解码时把像素换算成归一化坐标），与分辨率解耦。

**anchor（k-means 定制）**：不使用官方 COCO anchor —— 实测官方 anchor 最小的 3 个在本数据集
**分配占比 0%**（所有 GT 都被吸到最大尺度那层），每框最佳宽高 IoU 仅 0.567；
用训练集 k-means 聚类出的 anchor 后升到 **0.692**。

**正样本匹配（两级）**：
1. 按框的**等效边长**把 GT 分到 stride 8 / 16 / 32 的某一层（`level_scale=2.0`）；
2. 在该层的 3 个 anchor 里挑**宽高 IoU 最大**的那个，落在框中心所在网格。
（若 9 个 anchor 一起比 IoU，细尺度层会拿不到任何正样本。）

**损失**：
- obj / cls：**带正样本加权的 BCE**（正负样本各自取平均再加权），obj 分支偏置初始化为 **-2.0**；
- 框回归：**GIoU**（只对正样本算）。

**失败根因（结构层面）**：检测头输出的是**每个空间位置的密集 obj + cls 分数**，
而一张图只有 2~3 个缺陷框（正样本占候选位置约 **0.3%**）。结果是：
定位其实很准（在 GT 所属特征点上直接生成框，IoU 达 **0.742 / 0.757**），
但该框的 obj 分数只有 **0.056**、在 307 个候选里排 **第 135 位**，
被后处理 `top_k` 截断 → 验证集 mAP@0.5 恒为 0。

### 3.2 PP-YOLOE-s —— anchor-free、DFL 回归、四尺度

```
输入 640×640×3
└─ CSPResNet 主干（stem 一次下采样 + 4 个阶段，每阶段一次）
   stem   3×3/s2  → 64      /2
   stage1 /4  → 128   = 3×3/s2 下采样 + CSPLayer(3 块) + ESE
   stage2 /8  → 256   ──▶ f3 (80×80×256)
   stage3 /16 → 512   ──▶ f4 (40×40×512)    （CSPLayer 6 块）
   stage4 /32 → 1024  ──▶ f5 (20×20×1024)
└─ CSPPAN：三路 1×1 压到 256 → 自顶向下 2 层 → 自底向上 3 层
           并额外下采样出 P6（/64），共 4 层特征（stride 8/16/32/64）
           每层接一个 CSPRepLayer（瓶颈块换成可重参数化的 RepConv）
└─ 检测头 PPYOLOEHead（每层共享同一套权重）
   stem：2 × 3×3 ConvBN(256→128)
   ├─ cls 分支：3×3 卷积 → 6 通道，**偏置 = log(0.99/0.01) ≈ -4.6**（初始分数≈1%）
   └─ reg 分支：3×3 卷积 → 4×(reg_max+1) = 68 通道（DFL 分布回归，reg_max=16）
```

**无锚 + 简化版 ATL 正样本分配**：按框等效边长选层，再取框中心 **2.5 格**
（`center_radius=2.5`）范围内的锚点作正样本。

**损失**：分类用带正样本加权的 BCE；回归用 **DFL**（每条边学 17 个桶的分布，
小目标更友好）+ **GIoU**。DFL 的动机：直接回归一个数对边界不敏感，学分布更稳。

**其他结构件**：ESE 通道注意力（比原版 SE 省掉降维-升维，只用一个等宽全连接）；
`core/layers.py` 里还定义了 SPPF，但当前结构未使用（保留备用）。

**失败原因与 YOLOv3 同源**：同为"密集置信度 + 0.3% 正样本"，训练跑满也不收敛出可用排序。

## 四、两阶段方案（最终交付）

### 4.1 第一阶段：滑窗候选生成（**没有任何参数**）

在 200×200 原图上按如下组合枚举窗口：

| 项 | 取值 | 说明 |
|---|---|---|
| 尺度（占图短边比例） | **0.2, 0.3, 0.45, 0.65** | 上限曾试到 0.9，实测反而变差（大窗口必然覆盖缺陷、只增噪声） |
| 长宽比 | **0.35, 0.6, 1.0, 1.7** | 0.35 专为细长缺陷而加（In 夹杂 0.37、Sc 划痕 0.18） |
| 网格步长 | 12 像素 | 比 16 更密，候选的 IoU≥0.5 上限更高 |
| 候选数量 | **4624 个/图** | 尺度 × 长宽比 × 中心点 |

### 4.2 第二阶段 A：区域验证器 `DefectVerifier`（258.67 万参数）

```
候选框裁剪（向外扩 20% 边距）→ 缩放到 96×96（优化版 128）→ /255（优化版再加 ImageNet 归一化）
└─ mobilenet_v3_small(num_classes=1024)
     刻意把"分类头输出 1024 维"当作特征层用 —— 不依赖 paddle 内部的 features 等私有结构
└─ Dropout(0.3)
└─ Linear(1024 → 7)        6 类缺陷 + 1 背景
```

**训练样本**：GT 框作正样本；从「与所有 GT 的 IoU < 0.15」的区域随机取背景负样本。
（曾试过加"放大 GT 框"的难负样本，实测更差 —— 见 C 工作总结负面结论。）

### 4.3 第二阶段 B：区域精修器 `RegionRefiner`（259.08 万参数）

```
候选框裁剪（向外扩 15% 边距）→ 同上预处理
└─ 同一主干 mobilenet_v3_small → 1024 维特征
   ├─ cls_head: Linear(1024 → 7)    判类（与验证器口径一致）
   └─ reg_head: Linear(1024 → 4)    框修正量 (dcx, dcy, log dw, log dh)
```

**三个关键结构设计**：

1. **reg_head 权重与偏置零初始化** —— 训练初期"精修 ≈ 不改变框"，不会一上来就把已经对准的框推坏；
2. **偏移量相对候选框自身归一化**：`dcx = (gcx-cx)/cw`、`dlog w = log(gw/cw)`，
   与图像分辨率无关；解码时 `exp` 限幅 ±2（`decode_refine_batch` 与 numpy 版
   `decode_refine` 严格互为逆运算）；
3. **主干从验证器权重迁移**（`load_from_verifier`），训练更快更稳。

**训练样本**：以 GT 为基准抖动出"模拟候选" —— 尺度 0.2–0.65、长宽比 0.6–1.7、
中心抖动 ±0.25 倍框宽高；再混入与所有 GT 的 IoU < 0.1 的背景候选。
（这组抖动范围是 A/B 实测定的：放宽到 0.18–0.85 后合成指标更好看，但真实 mAP 反而从
0.2385 掉到 0.1289 —— 教训是"训练分布必须匹配推理分布"。）

**损失**：判类用交叉熵 + 框回归 **GIoU**（只对前景样本算回归，背景没有可回归的目标框）。
优化版把回归损失从"对归一化偏移做 L2"改成"把预测**解码成真实框**再算 IoU 系列指标"，
因为 AP@0.5 的命中门槛就是 IoU 0.5。

### 4.4 融合与后处理

```
p_defect = sqrt( (1 − pv_bg) · (1 − pr_bg) )      ← 缺陷概率：两个模型的几何平均
cls_c    = sqrt( pv_c · pr_c )                     ← 每类概率：几何平均
→ 阈值 0.6 → 按分数截 top_k = 150 → NMS(IoU = 0.4, max_det = 50)
```

**为什么用几何平均而不是算术平均**：几何平均更严格 —— 任何一个模型给出低分，
结果都不会被另一个模型强行拉高，符合"两个模型都同意才算真缺陷"的直觉。
实测这一层让 mAP 提升近一倍（滑窗＋精修器 0.0886 → 融合 0.1575）。
先截 `top_k` 再进 NMS 也是刻意的：候选极多时，先截可避免低分框参与 NMS 把高分框误压掉。

## 五、优化版在结构上改了三处

| 改动 | 结构层面做了什么 | 验证集 mAP 增益 |
|---|---|---|
| 主干换预训练 | `mobilenet_v3_small(pretrained=True)`，并新增 `prep_crop()` 统一输入管线补上 ImageNet 均值方差归一化 | **+0.0358** |
| 回归损失 L2 → GIoU | 新增 `decode_refine_batch`：把预测偏移解码成真实像素框，再直接算 GIoU | **+0.0132** |
| 输入 96 → 128 | 裁剪图块尺寸（ImageNet 特征本是在 224 下学的，96 一直在被过度下采样） | **+0.0302** |

`num_classes=1024` 恰好与 ImageNet 的 `classifier.0`（576→1024）同形，能吃到大部分预训练特征；
只有 `classifier.3`（1024→1000）形状不符被自动跳过 —— 而它本来就要重训。

**同步改善**：验证器图块准确率 0.8816 → **0.9564**；精修器 0.7795 → **0.8384**；
精修后平均 IoU 0.4442 → **0.4919**。整体：验证集 mAP@0.5 0.1681 → **0.2473**，
测试集 0.1552 → **0.2176**。

> ⚠️ `--norm`（none/imagenet）与 `--in-size` 必须与训练时一致，否则预训练特征会被错位的
> 输入分布稀释，而且**不报错**（静默掉点）。默认值保证历史行为逐位不变。

## 七、设计要点与踩过的结构坑

1. **全程归一化坐标**（`[0,1]` 的 xyxy / cxcywh）—— 数据、网络、解码、NMS、评估同一口径，
   评估阶段**零坐标反变换**。
2. **主干逐层写死，不用"循环 + 通道表"推导** —— 循环写法把 `/2`、`/4` 的位置搞错过 3 次，
   导致三个尺度整体错位（28/14/7 变成 14/7/4）。
3. **FPN / CSPPAN 的尺寸缩放用 `interpolate(size=[h, w])`，不用 `scale_factor=2`** ——
   200 输入时 25→12 是 0.48 而不是 0.5，硬写 2 倍会错位。
4. **只用原生算子**（`paddle.vision.ops.nms` 等），不编译自定义 OP、零新增依赖
   （不用 PaddleDetection 的原因见 [C 工作总结](C_检测任务工作总结.md) 第二节）。
5. **两阶段为什么能救**：单阶段要在上万个位置上**同时**学定位和置信度（极端稀疏监督）；
   两阶段把它拆成"在一块 96×96 图块上判是不是缺陷、是哪一类"（**稠密监督**），
   正负样本比例可控 —— 这个结构差异就是它能跑起来、而单阶段 mAP≈0 的根本原因。

## 九、复现

```bash
# 一键（推荐，会自动选对解释器）
python run_project.py --profile eval          # 只自检/汇总，看结果
python run_project.py --profile standard      # 训练两阶段模型并评估 val+test（GPU 约 1 小时）

# 最终方案手动两步
python src/det/train_verifier.py --name verifier_pre128 --pretrained --norm imagenet --in-size 128
python src/det/train_refiner.py  --name refiner_giou128 --pretrained --norm imagenet \
    --in-size 128 --reg-loss giou --init-verifier results/weights/verifier_pre128_best.pdparams

# 评估（--norm/--in-size 必须与训练一致）
python src/det/eval_fused.py --split test --mode fuse --stride 12 --score-th 0.6 \
    --nms-iou 0.4 --top-k 150 --max-det 50 --norm imagenet --in-size 128 \
    --verifier-weights results/weights/verifier_pre128_best.pdparams \
    --refiner-weights  results/weights/refiner_giou128_best.pdparams --tag test_fuse_pre128
```

命令细节与常见问题见 [`使用说明.md`](使用说明.md)。
